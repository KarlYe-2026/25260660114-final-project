# 每日 QQQ 估值观察 — 任务说明

> 长程工作流（long-running workflow）任务定义。实现与验收均以本文件为准。

## 1. 背景与目标

- **问题（Question）：** 每个美股交易日收盘后，判断 QQQ 最新收盘价是否低于两个"合理价值参考价"——200 日均线价与基于 NAV 的合理价——并给出"建议买入 / 观望"的观察信号。
- **读者（Audience）：** 用户本人，用于个人投资观察。**不构成投资建议**，输出中必须带此声明。
- **调度目标：** 无需人工干预，每个美股交易日自动运行一次；失败可诊断、可恢复。

## 2. 成功标准

1. 每个美股交易日北京时间 06:00 前自动完成一次运行，产出当日信号。
2. 两个参考价严格按第 5 节公式计算，信号规则唯一：收盘价**同时低于**两个参考价 → `建议买入`，否则 → `观望`。
3. 任一输入数据缺失时，当日信号为 `数据缺失`，**绝不默认给出买入/观望**。
4. 每次运行的结果必须通过双层 Critic 审查（第 4.2、4.3 节）；任一层不通过，运行状态记为 failed 并保留现场供人工复查。

## 3. 总体架构与数据流

```
Windows 任务计划程序 (每日 06:00 北京时间)
        │
        ▼
┌─────────────────────────────────────────────┐
│ ① 生产脚本  src/qqq_valuation.py             │
│   拉取数据 → 计算参考价与信号 → 写输出        │
└──────────────┬──────────────────────────────┘
               │ 原始数据快照 + 计算结果
               ▼
┌─────────────────────────────────────────────┐
│ ② Critic-1  独立校验脚本 src/validate.py     │
│   从原始数据独立重算 + 硬断言清单             │
└──────────────┬──────────────────────────────┘
               │ 通过 / FAIL + 问题清单
               ▼
┌─────────────────────────────────────────────┐
│ ③ Critic-2  LLM 终审（全新上下文，只读）      │
│   语义级审查：缺失处理、前视泄露、口径一致性   │
└─────────────────────────────────────────────┘
```

关键约束：② 和 ③ 都**不能盲目信任** ① 的输出。② 必须从原始数据独立重算全部指标；③ 只被给予输入快照、代码、输出和 ② 的报告，不接触 ① 的生成过程。

## 4. 组件设计

### 4.1 生产脚本 `src/qqq_valuation.py`

职责：取数、计算、落盘。参数：

- `--date YYYY-MM-DD`（可选）：历史回放模式，重放指定美股交易日；缺省为最近交易日。用于调试与验收。
- `--data-dir`、`--reports-dir`：路径覆盖，默认相对项目根目录。

处理步骤：

1. **取价格**：`yfinance` 下载 QQQ 日线，拉取窗口 ≥ 1 年（约 250 个交易日），字段用未复权 `Close`。价格单位美元，交易所日期（ET 日历）。
2. **取 NAV**：从 Invesco 官网 QQQ 产品页抓取最新公布的每份 NAV，解析出数值与公布日期。抓取器做成独立函数（`fetch_nav()`），便于更换数据源。**抓取失败 = NAV 缺失，按第 6 节处理，禁止静默跳过或沿用旧值冒充当日 NAV。**
3. **计算**：按第 5 节公式计算 `ma200`、`fair_nav`、信号。
4. **写输出**（全部只追加，不覆盖历史）：
   - `data/raw/YYYY-MM-DD.csv`：当日原始价格数据快照（重算的输入依据）
   - `data/processed/nav_history.csv`：追加一行 `date, nav, close, premium`
   - `data/processed/qqq_daily_log.csv`：追加一行 `run_id, asof_date, close, ma200, fair_nav, signal, data_status`
   - `report/YYYY-MM-DD.md`：当日人读报告（数值、信号、数据状态、免责声明）
   - `.state/state.json`：运行状态（见第 8 节）

### 4.2 Critic-1：独立校验脚本 `src/validate.py`

输入：`data/raw/` 当日快照、`data/processed/nav_history.csv`、生产脚本的当日输出行。它**独立导入自己的计算函数重算** `ma200` 与 `fair_nav`，然后执行硬断言，任一失败 → 退出码非 0，报告写入 `report/YYYY-MM-DD.critic1.md`：

| # | 断言 | 针对的风险 |
|---|------|-----------|
| 1 | 原始价格 `max(date) ≤ 运行对应的交易日 T`，且无重复日期 | 前视泄露 / 数据源混入未来数据 |
| 2 | 原始价格行数 ≥ 220，日期严格递增 | 窗口不足 / 数据缺口 |
| 3 | NAV 日期 == T；缺失时生产方必须已显式标记 `data_status=missing_nav` | 缺失数据被默认通过 |
| 4 | 重算的 `ma200`、`fair_nav` 与生产输出之差 < 1e-6 × 价格 | 生产脚本计算错误 |
| 5 | 按规则复算信号，与生产输出一致；`close == 参考价` 时必须为 `观望`（严格小于） | 信号规则实现偏差 |
| 6 | 当日 `run_id` 全局唯一，日志列完整 | 运行状态错乱 |

### 4.3 Critic-2：LLM 终审

每次运行后，在全新上下文（不继承生产会话的推理过程）中执行，只读材料：

- 当日原始数据快照（ prices + NAV 行）
- `src/qqq_valuation.py`、`src/validate.py` 源码
- 生产输出与 Critic-1 报告

审查清单：

1. **数据缺失**：缺失是否被如实标记？有无用旧 NAV、均值填充、前向填充冒充当日值？
2. **前视泄露**： rolling 窗口是否只含 ≤ T 的数据？有无 `.shift(-1)` 类未来函数？merge/join 键是否造成日期错位？历史回放模式是否会用到 `--date` 之后的数据？
3. **口径一致性**：均线、当前价、比较是否同一价格口径（都用未复权 Close）？单位/币种是否一致？
4. **结论一致**：报告文字描述与数值、信号是否相符？

结论（通过 / 不通过 + 问题清单）写入 `report/YYYY-MM-DD.critic2.md`。LLM 终审是对确定性断言的补充，**不替代** Critic-1 的硬断言。

### 4.4 调度：Windows 任务计划程序

- 触发：每日 06:00（北京时间）。美股 16:00 ET 收盘 = 北京时间次日 04:00（夏令时）/ 05:00（冬令时），06:00 运行时收盘数据已发布，全年安全。
- 入口：`src/run_daily.bat`，依次执行 `qqq_valuation.py`、`validate.py`，把退出码写入 `.state/state.json`。
- 安装命令（一次性，由用户执行或脚本安装）：

```bat

```

## 5. 指标与信号定义

记 T 为当日（信号日），`close_t`、`nav_t` 为 t 日收盘价与公布 NAV，所有数据均满足 `t ≤ T`（T 自身可用，因为信号在收盘后生成）。

```
premium_t     = close_t / nav_t − 1                      # 当日折溢价率
ma200_T       = mean(close_{T-199}, …, close_T)          # 含当日共 200 个交易日
fair_nav_T    = nav_T × (1 + mean(premium_{T-19}, …, premium_T))   # 20 日平均溢价调整
signal_T      = 建议买入  若 close_T < ma200_T 且 close_T < fair_nav_T
              = 观望      其他情况
```

设计说明：

- 参考价 2 用 20 日平均溢价而非当日裸 NAV：QQQ 日常折溢价仅 ±0.05% 量级，裸 NAV 信号一半是噪声；均值调整使参考价反映该 ETF 近期的典型溢价水平。
- 价格口径：均线与比较均用 yfinance 未复权 `Close`，口径自洽。QQQ 分红率低，复权跳变影响可接受；若日后切换调整价，两处必须同时切换（Critic-2 检查点）。
- 两条均线/参考价窗口的最早起点分别为 T-199 和 T-19，运行需保证原始数据 ≥ 220 行。

## 6. 数据缺失与前视泄露处理（预期情形，不是异常）

**缺失处理（按列独立判定）：**

| 缺失项 | 当日信号 | data_status |
|--------|----------|-------------|
| 收盘价不可得（数据源未更新） | `数据缺失` | `missing_close` |
| NAV 抓取失败 | `数据缺失` | `missing_nav` |
| 价格历史 < 220 行（窗口不足） | `数据缺失` | `insufficient_history` |
| Critic-1 任一硬断言失败 | 信号作废 | `validation_failed` |

- 禁止：用前一交易日 NAV 顶替、用均值/插值填补收盘价、把缺失日静默跳过。日志与报告必须逐日留痕，缺口一目了然。
-  holidays：非交易日不运行（脚本检测到最近交易日 < 运行日减阈值时直接记 `not_a_trading_day` 正常退出）。

**前视防线（三道）：**

1. 计算侧：只用 `date ≤ T` 切片；历史回放模式先把数据截断到 T 再计算。
2. Critic-1 断言 #1、#2（未来日期、窗口完整性）。
3. Critic-2 语义审查（未来函数、日期对齐错误）。

## 8. 运行状态与失败恢复

`.state/state.json` 每次运行覆写：

```json
{
  "run_id": "2026-06-20T06:00:01+08:00",
  "data_asof": "2026-06-19",
  "status": "success | data_missing | validation_failed | error",
  "validation": "pass | fail",
  "last_success_output": "report/2026-06-19.md",
  "reviewer": "critic1: pass, critic2: pending"
}
```

- **输入截止**：运行时刻；数据 as-of 日 T 为运行时刻之前最近的美股交易日。
- **失败恢复**：任何一步失败不删除已有产物；下次运行从上次成功状态继续（日志追加式，天然幂等）。
- **人工复查入口**：`python src/qqq_valuation.py --date YYYY-MM-DD` 可重放任意历史交易日，配合当日 raw 快照复现。

## 9. 验收测试

实现完成后必须全部通过：

1. **手算核对**：任取一个交易日，手工（或 Excel）计算 200 日均线与 20 日平均溢价调整价，与脚本输出误差 < 1e-6 × 价格。
2. **历史回放**：`--date` 重放一个已知行情日（如一段 QQQ 明显低于 200 日线时期），信号方向与当时市况常识一致。
3. **缺失注入**：删除当日 NAV 行 → Critic-1 必须判 `missing_nav` 且信号为 `数据缺失`；截短价格历史 → 断言 #2 触发。
4. **前视注入**：把快照中某日期人为改到 T 之后 → Critic-1 断言 #1 必须 FAIL。
5. **边界测试**：构造 `close == ma200` 或 `close == fair_nav` 的合成数据 → 必须输出 `观望`（严格小于）。
6. **端到端**：安装计划任务后，手动触发一次 `run_daily.bat`，全链路产物齐备，`state.json` 为 success。

## 10. 已知限制与非目标

- NAV 抓取依赖 Invesco 网页结构，可能失效；失效时按缺失处理，fetcher 设计为可替换。这是本工作流最脆弱的一环，Critic-1 断言 #3 专职盯守。
- 未复权口径下，QQQ 分红除息日会造成均线与价格的微小口径跳变（已在第 5 节说明取舍）。
- 本工作流输出的是**价格相对参考位的观察信号**，不是内在价值分析；单日信号噪声大，仅供个人长期观察。
- **非目标**：不预测价格、不做组合回测与收益归因、不推送通知（如需可后续扩展）。
